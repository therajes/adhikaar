# 90-second judge flow

1. On one browser/device, choose **Citizen** and use the one-click fictional citizen account. Point out the Supabase-protected session and read the eight-character challenge aloud.
2. In a separate browser profile/device, choose **Organisation**, enter the fictional employee account, and show that membership and role came from protected institution records.
3. Enter the citizen challenge, select “Confirm masked reference,” create the 90-second signed proof and read its six-character code.
4. Enter that code on the citizen device. Show **Verified and authorised** and expand the technical proof to identify Swift WebAssembly.
5. On the employee side, click the blocked OTP demonstration. Show that normal issuance refuses it before a proof can be shared.
6. Sign in as the fictional institution administrator. Show the signed allowlist and explain invite → protected role → device binding → credential issuance.
7. Open Safety Lab and run all 12 checks. Point to the genuine-key/off-policy fixture returning **Authentic representative — unauthorised request**.
8. Open the validator simulator and execute or inspect the real two-of-three Anvil governance state. Explain that only hashes—not citizen or employee personal data—go on-chain.
9. If time permits, publish an immutable employee revocation and re-check the previously issued code on the citizen device to show **Credential revoked**.

Keep the answer to phone integration precise: the prototype is an out-of-band cryptographic companion to the call. A production CRM, dialler, registered SMS/RCS sender or IVR can deliver the proof; ADHIKAAR does not claim to listen to the conversation.
